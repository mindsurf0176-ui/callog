# 칼로그 (Callog) — 사진 기반 칼로리 추정

사진 한 장으로 식사의 칼로리와 영양을 추정하는 [앱인토스](https://toss.im) 미니앱입니다. 멀티모달 LLM의 반복적인 과소추정을 프롬프트만으로 감추지 않고, 실측 벤치마크와 5단계 보정 파이프라인으로 줄였습니다.

> 상용 앱 소스는 비공개입니다. 이 저장소는 문제 정의, 실제 화면, 설계와 검증 결과를 공개합니다.

## 한눈에 보기

| | |
|---|---|
| **Role** | 제품·AI 파이프라인 1인 설계·구현 |
| **Problem** | 피자·파스타 등 고열량 음식의 반복적인 과소추정과 결과 흔들림 |
| **Build** | 기준물체·영양 DB·CalorieCLIP·규칙 보정·2-tier 모델 폴백 |
| **Proof** | Nutrition5k 통과율 **70→88%**, 중앙 절대 백분율 오차(MdAPE) **31→19%** |

## 해결 구조

```text
이미지 입력
  → 기준물체 캘리브레이션 + grounding
  → 식약처 영양 DB 그라운딩
  → CalorieCLIP 앙상블 (과소추정 방어에만 제한 적용)
  → 규칙 기반 보정 엔진
  → 저신뢰 결과만 상위 모델로 폴백
```

- 기준물체로 양을 추정하고 식약처 영양 DB 28.2만 건으로 품목을 보정합니다.
- CalorieCLIP 결과는 과소추정 방어 조건을 통과할 때만 반영합니다.
- 확신이 낮은 요청만 상위 모델로 보내 정확도와 비용을 함께 관리합니다.

## 검증

Nutrition5k 50개 요리를 고정 평가셋으로 사용했습니다. 파이프라인 변경마다 같은 입력을 다시 실행해 통과율과 중앙 절대 백분율 오차를 비교했습니다.

| Metric | Baseline | Current |
|---|---:|---:|
| 허용 오차 기준 통과율 | 70% | **88%** |
| 중앙 절대 백분율 오차(MdAPE) | 31% | **19%** |

현재 허용 오차 기준 통과는 `44/50`입니다. 보정 엔진은 통계 모델이 아니라 도메인 규칙이며, 위 수치는 50개 평가셋의 중앙값과 통과율입니다. 전체 음식에 대한 일반 정확도나 평균 MAPE로 확대해 해석하지 않습니다.
